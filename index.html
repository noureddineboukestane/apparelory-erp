// GUIDE OPÉRATIONNEL & LOGICIEL

Comment fonctionne chaque module d'Apparelory ERP ?

Plongez dans les détails techniques et méthodologiques qui font tourner l'application au quotidien.

01

Gestion du Catalogue & SKU

Chaque référence dispose d'un identifiant unique (SKU), d'une désignation claire, d'une catégorie et d'un fournisseur attitré. Lors de la création, vous pouvez associer une miniature photo stockée localement dans `images_produits/` ou générée automatiquement par le système.

Validation SKU: UNIQUE Actif
02

Entrées de Stock & Réassort

Lors d'une entrée de lot, l'administrateur renseigne la quantité reçue et le nouveau prix d'achat. Le système met à jour la quantité totale et recalcule mathématiquement le CUMP pour refléter la valeur réelle du capital immobilisé en entrepôt.

Moteur: Pondération dynamique Automatique
03

Sorties & Facturation Client

Pour chaque vente ou sortie exceptionnelle, l'application vérifie la disponibilité physique. Si le stock est suffisant, la quantité est déduite et une facture PDF normalisée (avec en-tête, nom du client et total en devise) peut être éditée et sauvegardée instantanément.

Formats: PDF & CSV Instantané
04

Sécurité & Contrôle des Rôles

Le système intègre deux profils d'accès : Admin (contrôle total sur les prix d'achat, les fournisseurs et les seuils) et User/Vendeur (interface simplifiée avec masquage automatique des marges et des prix d'achat confidentiels).

Authentification: Sécurisée Multi-niveaux
// SCHÉMA RELATIONNEL SQLITE / POSTGRESQL

Modélisation rigoureuse des données

La structure repose sur trois tables principales interconnectées pour garantir l'intégrité référentielle, éviter les redondances et assurer un historique irréprochable de chaque mouvement de stock.

SQL / Relational 
CREATE TABLE fournisseurs (
    id SERIAL PRIMARY KEY,
    nom_entreprise TEXT,
    telephone TEXT
);

CREATE TABLE articles (
    sku TEXT PRIMARY KEY,
    designation TEXT,
    fournisseur_id INTEGER REFERENCES fournisseurs(id),
    quantite_actuelle INTEGER DEFAULT 0,
    prix_achat NUMERIC DEFAULT 0.0,
    seuil_alerte INTEGER DEFAULT 50
);

CREATE TABLE historique (
    id SERIAL PRIMARY KEY,
    date_mouv TEXT,
    sku TEXT REFERENCES articles(sku),
    operation TEXT,
    quantite INTEGER,
    client TEXT DEFAULT ''
);
// MOTEUR MATHÉMATIQUE

Pensé par un Logisticien.
Codé pour la précision financière.

La méthode du Coût Unitaire Moyen Pondéré garantit une valorisation comptable irréprochable, indispensable dans la gestion des stocks.

ALGORITHME FINANCIER MODULE_CUMP

Valorisation dynamique après réapprovisionnement

Le système calcule automatiquement la pondération entre l'ancien stock existant et le nouveau lot entrant.

// Formule mathématique officielle :
Nouveau_CUMP = ( (Stock_Actuel × Ancien_CUMP) + (Qté_Entrée × Prix_Lot) ) / Stock_Total
